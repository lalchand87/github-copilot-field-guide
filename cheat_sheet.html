IDEMPOTENCY PATTERNS
• Client UUID — generated before first send; same key on retry
• PUT / upsert — natural idempotency, no key needed
• ON CONFLICT DO NOTHING — deduplicate by event_id in DB
• Kafka enable.idempotence=true — producer dedup

⚡Common Interviewer Traps

What the interviewer will ask — and what the Staff answer is

PatternThe trap questionStaff-level answer
Real-TimeWhat if a user has 10M followers?Hybrid fan-out: push for regular users, pull on read for celebrities
ContentionHow do you prevent double-charge on retry?Client-generated idempotency key; optimistic lock with WHERE balance ≥ amount
Multi-StepStep 4 is irreversible and fails — now what?DLQ + manual review queue; irreversible steps are placed last
Scale Reads1000 requests hit DB simultaneously after cache expiresCache stampede; XFetch or mutex lock; TTL jitter prevents recurrence
Scale WritesOne shard gets all the trafficHot shard; add entropy to partition key; virtual shards
Long TasksJob runs twice after worker crashIdempotent workers: check if output already exists before processing
SearchNew products take 30 seconds to appear in searchCDC → Kafka → ES indexer; tune refresh_interval; monitor consumer lag
Rate LimitingRedis is down — do you fail open or closed?Auth endpoints: fail closed. API endpoints: fail open with alert. Document the choice.
Dist. TxnOrchestrator crashes after debit but before creditState persisted before each step; orchestrator resumes from DB; idempotency key on credit
Multi-RegionUser travels from India to EU — which region serves them?Redirect to home region; or cross-region proxy with documented latency cost
API GatewayAuth service is down — can users still make API calls?JWKS cached at gateway (TTL 5–10min); existing valid tokens work until cache expires
