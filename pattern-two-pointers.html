01. The Core Idea — Two Flavors

Flavor 1 — Opposite ends, moving inward

Used for: palindrome check, two sum (sorted), container with most water, trapping rain water. Left starts at 0, right at n-1, they move toward each other.

Flavor 2 — Same direction, different speeds

Used for: remove duplicates in place, fast/slow pointer problems, partitioning. Both pointers start together and move rightward, but one advances more often/faster than the other.

⚠ Interview Trap

Opposite-end two pointers requires sorted input (or a monotonic structure) — without it, you don't know which pointer "should" move. Same-direction two pointers doesn't need sorted input; it's about read/write speed, not value comparison.
💡 Ask yourself first: are my two pointers walking toward each other, or in the same direction at different speeds? That answers which flavor you need.

02. Valid Palindrome (with cleanup)

s = "A man, a plan, a canal: Panama" → ignore case and non-alphanumeric characters, then compare from both ends.

int left = 0, right = s.length() - 1;
while (left < right) {
    while (left < right && !Character.isLetterOrDigit(s.charAt(left)))  left++;
    while (left < right && !Character.isLetterOrDigit(s.charAt(right))) right--;
    if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right)))
        return false;
    left++; right--;
}
return true;

⚠ Interview Trap

Skip-while-invalid loops need their own left < right bound check, or they can run past the other pointer entirely on strings with lots of punctuation.

Pattern Recognition

"Palindrome with noise to ignore" → same opposite-end two pointers as the clean version, just with inline filtering before each comparison.
💡 Cleanup and comparison happen inline, in the same pass — no need for a separate filtering pass first.

03. 3Sum

nums=[-1,0,1,2,-1,-4] → find all unique triplets summing to 0. Sort first, then fix one element and two-pointer the rest.

Sorted[-4, -1, -1, 0, 1, 2]
Fixed iLeftRightSumAction
-4 (i=0)-12-3too small → left++
-4 (i=0)-12-3...no triplet found for -4
-1 (i=1)021too big → right--
-1 (i=1)010✅ found [-1,0,1], move both, skip dupes
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue; // skip duplicate "fixed" values
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) {
            result.add(List.of(nums[i], nums[left], nums[right]));
            while (left < right && nums[left] == nums[left+1]) left++;  // skip dupes
            while (left < right && nums[right] == nums[right-1]) right--;
            left++; right--;
        } else if (sum < 0) left++;
        else right--;
    }
}

⚠ Interview Trap

Duplicate skipping is required at THREE points: the fixed outer element, and both inner pointers after a match — miss any one and you get duplicate triplets in the output.

Complexity

O(n²) — O(n log n) sort + O(n) outer loop × O(n) inner two-pointer scan.
💡 3Sum = "fix one element, reduce to 2Sum on the rest" — this fix-and-reduce trick generalizes to 4Sum and beyond.

04. Container With Most Water

heights=[1,8,6,2,5,4,8,3,7] → maximize area between two lines. Start with the widest container (both pointers at the ends), and always move the SHORTER side inward — moving the taller side can only shrink width without any chance of increasing height.

LeftRightWidthHeight=min(L,R)AreaMove
1 (idx0)7 (idx8)818move left (shorter)
8 (idx1)7 (idx8)7749move right (shorter)
int left = 0, right = heights.length - 1, maxArea = 0;
while (left < right) {
    int area = Math.min(heights[left], heights[right]) * (right - left);
    maxArea = Math.max(maxArea, area);
    if (heights[left] < heights[right]) left++;
    else right--;
}

⚠ Interview Trap

Why moving the shorter side is provably correct, not just a heuristic: the area is bounded by the SHORTER wall. Moving the taller wall inward keeps that same shorter-wall bound (or makes it worse) while definitely shrinking width — so it can never help. Moving the shorter wall is the only move that has any chance of increasing the bounding height.

Complexity

O(n) — beats the O(n²) brute-force check of every pair.
💡 Always move the pointer at the shorter wall — that's the one and only insight this problem is testing.

05. Trapping Rain Water (two-pointer version)

height=[0,1,0,2,1,0,1,3,2,1,2,1] → water at index i = min(maxLeft, maxRight) − height[i]. Two pointers avoid precomputing full maxLeft[]/maxRight[] arrays.

int left = 0, right = n - 1, leftMax = 0, rightMax = 0, water = 0;
while (left < right) {
    if (height[left] < height[right]) {
        leftMax = Math.max(leftMax, height[left]);
        water += leftMax - height[left];
        left++;
    } else {
        rightMax = Math.max(rightMax, height[right]);
        water += rightMax - height[right];
        right++;
        right--; // (advance right pointer inward)
    }
}

Why comparing height[left] vs height[right] is safe

Whichever side is shorter, THAT side's water level is bounded by its own running max — because there's guaranteed to be a taller wall somewhere on the other side (that's exactly why we chose to process the shorter side). So you never need the other side's exact max, only that it's ≥ your current side.

Pattern Recognition

Same "process the shorter/weaker side" insight as Container With Most Water — a recurring theme across two-pointer problems where one side bounds the answer.
💡 Same family as Container With Most Water: process the side that's currently the bottleneck, because the other side is guaranteed not to be.

06. Same-Direction — Remove Duplicates In Place

nums=[1,1,2,2,3] (sorted) → remove duplicates in place, return new length. "Slow" pointer marks where the next unique value should be written; "fast" pointer scans ahead looking for it.

slowfastCompareActionArray state
01nums[1]==nums[0]skip (duplicate)[1,1,2,2,3]
02nums[2]!=nums[0]slow++, nums[slow]=nums[2][1,2,2,2,3]
13nums[3]==nums[1]skip (duplicate)[1,2,2,2,3]
14nums[4]!=nums[1]slow++, nums[slow]=nums[4][1,2,3,2,3] → length=3
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
return slow + 1; // new length

Pattern Recognition

"Modify array in place, O(1) space, based on a scan condition" → same-direction slow/fast pointer, read pointer scans ahead of write pointer.
💡 Same-direction two pointers: fast reads everything, slow only writes what deserves to stay.

07. Mistakes to Avoid & Recap

⚠ Common Mistakes

  • Applying opposite-end two pointers to unsorted data without sorting first
  • Moving the taller/larger side in Container/Rain Water problems instead of the shorter/bounded side
  • Missing duplicate-skip logic in 3Sum/4Sum, producing duplicate results
  • Confusing same-direction (read/write speed) with opposite-end (value comparison) — different bugs come from each

Toolbox recap

Opposite-end (palindrome, sorted 2Sum/3Sum, container, rain water) · Same-direction (remove duplicates, partitioning) · Fix-and-reduce (3Sum → 2Sum, generalizes to K-Sum)
💡 Two pointers work because there's always a reason ONE specific pointer should move — find that reason and the algorithm writes itself.
