01. Strings — Start Here

A string is just a sequence of characters, indexed from 0. Everything else in this deck builds on that one idea: knowing where a character sits, and how many sit between two points.

Key Terms

  • Character — smallest unit ('H', '7', '@')
  • Index — position of a character
  • Length — total character count
  • Empty string — "", length 0
  • Concatenation — joining two strings: "Hello"+"World"="HelloWorld"

Quick Access Patterns

  • First char → s[0] → 'H'
  • Last char → s[length-1] → 'O'
  • Substring idx 1→3 → s.substring(1,4) → "ELL"
  • In Java, String is immutable — every "modification" creates a new object

⚠ Interview Trap

In Java, repeated + concatenation inside a loop is O(n²) overall because each concat allocates a new String. Use StringBuilder for loop-based building — this is a very common senior-level red flag if missed.
💡 Always clarify character set, case sensitivity, and valid inputs before solving — most bugs come from unstated assumptions, not logic errors.

04. Frequency Counting / Hashing

Many string problems reduce to "how many times does each character appear." Example: S = "BANANA"

1. Frequency Array

Best when the character set is small & known (e.g. lowercase a-z). 
int[] freq = new int[26];
for (char c : s.toCharArray())
    freq[c - 'a']++;
Good for: fixed ASCII ranges, tight memory.

2. HashMap

Best when the character set is large/unknown (Unicode, case-sensitive, mixed symbols). 
Map<Character,Integer> freq = new HashMap<>();
for (char c : s.toCharArray())
    freq.merge(c, 1, Integer::sum);

Pattern Recognition

If the problem asks for: anagram check · isomorphic strings · duplicate characters · first non-repeating char · k most frequent chars · occurrence analysis → think Frequency Counting.

Complexity

Time: O(n) — one pass. Space: O(k), k = distinct characters.
💡 Small fixed alphabet → array. Anything else → HashMap.

05. Two Pointers — Palindrome Check

Two pointers start at opposite ends and move inward, comparing as they go. S = "RACECAR"

StepLeft / RightCompareResult
1L=0 (R) / R=6 (R)S[0]=='R', S[6]=='R'match → move inward
2L=1 (A) / R=5 (A)S[1]=='A', S[5]=='A'match → move inward
3L=2 (C) / R=4 (C)S[2]=='C', S[4]=='C'match → move inward
4L=3 (E) / R=3 (E)pointers meet✅ Palindrome
int left = 0, right = n - 1;
while (left < right) {
    if (s.charAt(left) != s.charAt(right)) return false;
    left++; right--;
}
return true;

⚠ Interview Tip — Don't Forget

  • Empty string / single character → always a palindrome
  • Case sensitivity — define it explicitly with the interviewer
  • "Ignore non-alphanumeric" variant (e.g. "A man, a plan, a canal: Panama") needs a cleanup pass first

Pattern Recognition

Comparing characters from both ends toward the middle → think Two Pointers.

Complexity

Time: O(n). Space: O(1) — no extra structure needed.
💡 Two pointers turn an O(n) space palindrome check into O(1) space — always the follow-up interviewers push for.

06. Sliding Window

Problem: Longest substring without repeating characters. S = "ABCABCBB"

ActionLRWindowSetResult
expand R00[A]{A}valid, len=1
expand R01[A,B]{A,B}valid, len=2
expand R02[A,B,C]{A,B,C}valid, len=3
expand R03[A,B,C,A]{A,B,C,A}duplicate A
shrink L13[B,C,A]{B,C,A}valid, len=3
expand R14[B,C,A,B]—duplicate B
shrink L24[C,A,B]{C,A,B}valid, len=3
int left = 0, maxLen = 0;
Set<Character> window = new HashSet<>();
for (int right = 0; right < s.length(); right++) {
    while (window.contains(s.charAt(right))) {
        window.remove(s.charAt(left));
        left++;
    }
    window.add(s.charAt(right));
    maxLen = Math.max(maxLen, right - left + 1);
}

Pattern Recognition

"Longest/shortest contiguous substring with a condition" → think Sliding Window.

Complexity

Time: O(n) — each char enters/leaves window once. Space: O(k), k = unique chars in window.
💡 Expand right greedily, shrink left only when the window breaks the rule — never restart from scratch.

07. String Matching — KMP

Naive matching re-checks characters after every mismatch. KMP avoids that using an LPS array (Longest Prefix that is also a Suffix) to skip ahead in the pattern intelligently.

LPS array — Pattern = "ABABACABA"

i012345678
P[i]ABABACABA
LPS[i]001230123
Build rule: compare P[i] with P[len]. Match → len++, LPS[i]=len. Mismatch & len>0 → len=LPS[len-1] (backtrack, don't advance i). Mismatch & len==0 → LPS[i]=0.

Search walkthrough — Text "ABABCABAB", Pattern "ABAB"

Stepi(text)j(pattern)CompareAction
100A==Amatch, i++,j++
211B==Bmatch, i++,j++
322A==Amatch, i++,j++
433B==Bmatch, i++,j++
544j==mfound at index 0

Complexity

Preprocess O(m), search O(n), total O(n+m). Beats naive O(n·m).

⚠ Interview Trap

People forget the LPS build uses P[i] vs P[len], not P[i] vs P[i-1]. That off-by-one is the #1 KMP bug.
💡 KMP shines when the same pattern is searched many times in a large text — the LPS array is what lets it never re-scan.

08. Rabin-Karp — Rolling Hash

Instead of comparing characters one by one, compute a hash for each window and compare hashes. A rolling hash updates the hash for the next window in O(1) instead of recomputing from scratch.

Rolling hash formula

H(i+1) = ((H(i) − T[i]×h) × d + T[i+m]) mod q

d = base (e.g. 256 for ASCII), q = large prime modulus, h = d^(m-1) mod q (used to remove the leading char's contribution).

Why the modulus q?

  • Prevents integer overflow on large texts
  • Reduces hash collisions
  • Keeps hash values in a bounded range [0, q-1]

Complexity

Best/avg: O(n+m). Worst (many collisions): O(n·m) — always verify on hash match!

Real-world use

Plagiarism detection · DNA sequence matching · file/virus signature scanning · network intrusion detection.
💡 A hash match is a candidate, not a confirmed match — always verify characters to rule out collisions.

10. Advanced String Problems

Longest Palindromic Substring

s="babad" → "bab" or "aba". Expand around center: for each index (and each gap between indices), grow outward while characters match.
Time O(n²), Space O(1)

Minimum Window Substring

s="ADOBECODEBANC", t="ABC" → "BANC". Sliding window: expand right until all of t is covered, then shrink left while still valid, tracking the minimum.

Check Anagrams

"listen"/"silent" → true. Sort + compare (O(n log n)) or frequency map (O(n), O(1) space for 26 letters).

String Rotation Check

Is s2 a rotation of s1? Check s2 ∈ (s1+s1). "waterbottle"+"waterbottle" contains "erbottlewat" → true.

⚠ Mistakes to Avoid

  • Off-by-one errors at window/pointer boundaries
  • Ignoring case sensitivity or whitespace when the problem didn't specify
  • Not handling empty-string / single-char edge cases
  • Inefficient repeated string concatenation instead of StringBuilder

Toolbox recap

HashSet/HashMap (frequency, dedup) · Frequency array (fixed alphabet) · Two Pointers (palindrome, in-place) · Sliding Window (substring conditions) · KMP / Rabin-Karp (pattern search) · DP (longest common substring/subsequence)
💡 Strings are everywhere in interviews — the pattern (not the problem) is what you should be memorizing.
